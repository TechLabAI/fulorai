# TechLab AI Integration — ASST (`document_composition`)

> ASST delegates **all** AI capability to TechLab AI over HTTP. The BE **never** calls an AI
> provider (Anthropic/OpenAI/etc.) directly. This contract is consumed alongside the global
> `docs/architecture/integrations/techlab-ai-integration.md`.
>
> **Status:** the exact endpoints/DTOs are **pending the upstream SHA pin** — P3
> (`integrations/techlab-ai/openapi.json`) is still a placeholder. This document specifies the
> *expected* surface and the exact coupling point; it is finalized when the SHA is pinned and the
> Java DTOs are generated by `openapi-generator-cli` into `gen/techlabai/`.

## 1. Capabilities consumed

| Capability | Use in ASST | Mode |
|---|---|---|
| `document_composition` | **Asset Studio** — compose/edit asset content from a brief + tenant context | sync (timeout + circuit breaker) |
| classification/tagging | **Asset Intelligence** — suggest tags + classify on create/publish | sync best-effort (non-blocking) |

## 2. Operations (expected)

### Compose (Asset Studio)
- Client: `TechLabAiClient` in `infrastructure.clients` (HTTP; **not** a `@FeignClient` — DTOs generated from `openapi.json`).
- Request (logical): `{ tipoAsset, brief, contexto, baseConteudo? }`.
- Response (logical): `{ conteudo, metadados }` → mapped to a new `versao_asset` (origem=ASSET_STUDIO).
- `WHEN the Asset Studio calls document_composition AND it returns within the timeout, THE SYSTEM SHALL persist the result as a new RASCUNHO version with brief_composicao recorded.`
- `IF document_composition fails, times out, or the circuit is open, THEN THE SYSTEM SHALL respond 503 error.code 'asst.studio.ia-indisponivel' AND SHALL NOT create a version.`

### Classify (Asset Intelligence)
- `WHEN an asset is created or published, THE SYSTEM SHALL request a classification/tag suggestion AND SHALL persist suggested tags with origem=IA.`
- `IF classification is unavailable, THEN THE SYSTEM SHALL proceed without IA tags (best-effort, non-blocking).`

## 3. Resilience

- **Timeout:** `TECHLAB_AI_TIMEOUT_MS` (default 20000 ms).
- **Circuit breaker (Resilience4j):** open at `TECHLAB_AI_CB_FAILURE_RATE` (default 50%); half-open probes.
- **Fallback:** graceful degradation — CRUD, versioning, approval and publication never depend on TechLab AI availability (ADR-003).
- **No retries on composition** beyond the client default (avoid duplicate generations); idempotency via `Idempotency-Key` (SPEC-05).

## 4. Header propagation

- `X-Correlation-Id` propagated to TechLab AI (traceability across services).
- Tenant identity (`empresaId`) and principal passed per the global integration contract (claim/header) — finalized with the pinned contract.
- Auth to TechLab AI per `TECHLAB_AI_JWT_ENABLED` (disabled locally).

## 5. DTO generation

- DTOs are auto-generated from `integrations/techlab-ai/openapi.json` into
  `backend/services/asst-service/src/main/gen/techlabai/dtos/` by `openapi-generator-cli` at
  scaffold time — **never hand-written, never edited**. Regenerated when the source SHA updates.
