# TechLab AI Integration — JRNY (`orchestration`)

> JRNY delegates **all** AI capability to TechLab AI over HTTP. The BE **never** calls an AI
> provider (Anthropic/OpenAI/etc.) directly. This contract is consumed alongside the global
> `docs/architecture/integrations/techlab-ai-integration.md`.
>
> **Status:** the exact endpoints/DTOs are **pending the upstream SHA pin** — P3
> (`integrations/techlab-ai/openapi.json`) is still a placeholder. This document specifies the
> *expected* surface and the exact coupling point; it is finalized when the SHA is pinned and the
> Java DTOs are generated by `openapi-generator-cli` into `gen/techlabai/`.
>
> **Core principle (ADR-005):** the assist is **always optional**. The deterministic Routing
> Engine is the reference path and **never** depends on TechLab AI availability.

## 1. Capabilities consumed

| Capability | Use in JRNY | Mode |
|---|---|---|
| `orchestration` | **Routing Engine assist** — recommend the next-best stage/action from the lead + journey context | sync (short timeout + circuit breaker), **optional** |

## 2. Operations (expected)

### Recommend next stage (Routing Engine assist)
- Client: `TechLabAiClient` in `infrastructure.clients` (HTTP; **not** a `@FeignClient` — DTOs generated from `openapi.json`).
- Request (logical): `{ leadSnapshot: { scoreAgregado, dimensoes, segmentoId, atributos }, jornada: { id, versao, estagios[] }, estagioCorrenteId }`.
- Response (logical): `{ estagioRecomendadoId, confianca, justificativa }` → folded into the deterministic decision.
- `WHEN the Routing Engine consults orchestration AND it returns within the timeout, THE SYSTEM SHALL fold the recommendation into the decision and record assist_ia=USADO with the suggestion and confidence in snapshot_entrada.`
- `IF orchestration fails, times out, or the circuit is open, THEN THE SYSTEM SHALL decide using deterministic rules only and record assist_ia=INDISPONIVEL, never blocking the decision.`
- `IF a deterministic guard rule marked mandatory applies, THEN THE SYSTEM SHALL honor the rule over the AI recommendation and record assist_ia=IGNORADO.`

## 3. Resilience

- **Timeout:** `TECHLAB_AI_TIMEOUT_MS` (default **2000 ms** — short, because routing is on the golden path).
- **Circuit breaker (Resilience4j):** open at `TECHLAB_AI_CB_FAILURE_RATE` (default 50%); half-open probes.
- **Fallback:** deterministic routing — journey definition, rule evaluation, enrolment, advance and the decision log never depend on TechLab AI availability (ADR-003/ADR-005).
- **No retries** on the assist call beyond the client default (the decision must stay fast; a missed assist is a graceful `INDISPONIVEL`, not a failure).

## 4. Header propagation

- `X-Correlation-Id` propagated to TechLab AI (traceability across services).
- Tenant identity (`empresaId`) and principal passed per the global integration contract (claim/header) — finalized with the pinned contract.
- Auth to TechLab AI per `TECHLAB_AI_JWT_ENABLED` (disabled locally).

## 5. DTO generation

- DTOs are auto-generated from `integrations/techlab-ai/openapi.json` into
  `backend/services/jrny-service/src/main/gen/techlabai/dtos/` by `openapi-generator-cli` at
  scaffold time — **never hand-written, never edited**. Regenerated when the source SHA updates.

## 6. Coupling point (gap marker)

Until the SHA is pinned, the Routing Engine codes against the `RecomendacaoIaPort` (out) interface
with the *expected* request/response above; the only thing that changes at SHA-pin time is the
generated DTO wiring inside `TechLabAiClient`. The deterministic path is fully specified and tested
independently of this gap (SPEC-02, `routing-decision.feature`).
