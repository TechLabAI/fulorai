## 0. Leitura executiva

### Papel do servico (extraido de 01-architectural-vision.md)
Single, well-known service-discovery authority (Netflix Eureka Server) so backend services
and the API Gateway locate each other by logical name, never by hardcoded host/port.

### MVP scope (extraido de 01)
Standalone single-node Eureka Server on port 8761; dashboard at `/`; Actuator `health`/`info`;
self-preservation tuned per profile; does not register with itself; env-driven config.

### Diagnostico inicial (gaps mapeados em 06)
- R1 single point of failure (single node) — mitigated by client-side cached registries; HA deferred (ADR-005).
- R2 unsecured dashboard — mitigated by network restriction; dashboard auth out of MVP scope.
- R3 self-preservation tuning — handled per profile (P2).
Infra module: no domain, persistence, messaging, or multi-tenancy (ADR-001/003/004).

## 1. Estrategia geral

### Objetivo macro
Stand up a correct, boring, env-driven Eureka Server that other services can register with,
with a health contract for orchestration and a guard on the base package.

### Ordem das prioridades

| P | Titulo | Motivo |
|---|---|---|
| P1 | Scaffold + base config | Executable Eureka Server is the prerequisite for everything |
| P2 | Profiles + self-preservation | Correct eviction behavior per environment (ADR-005) |
| P3 | Observability + health | Probeable health + service-tagged logs for ops |
| P4 | Architecture guard | Enforce RULE-09 base package (only applicable ArchUnit rule) |

## 2. Plano por prioridade

### Prioridade 1 -- Scaffold + base config
Status: pendente

#### Objetivo / Resultado esperado
A bootable Eureka Server on 8761 that does not register with itself and exposes only
`health`/`info` Actuator endpoints.

#### Issues vinculadas
- REG-001
- REG-002

#### Specs cobertas
- SPEC-01-api-surface
- SPEC-06-security (actuator exposure portion)

#### Sequencia de execucao
- Fase 1: `RegistryApplication` + Gradle subproject + Eureka/Actuator deps (REG-001).
- Fase 2: `application.yml` base config (REG-002).

#### Criterios de aceite
- `bootRun` starts; `GET /` dashboard; `GET /actuator/health` = UP; self-registration off.

#### Riscos
- Spring Cloud / Spring Boot 3.5.x BOM alignment for the Eureka starter.

#### Instrucao para implementador
Generated by scaffold (be-module-generator.py, type=registry). Verify the two issues' acceptance criteria post-scaffold.

### Prioridade 2 -- Profiles + self-preservation
Status: pendente

#### Objetivo / Resultado esperado
Profile-specific self-preservation + advertised hostname.

#### Issues vinculadas
- REG-003

#### Specs cobertas
- SPEC-07-observability-health (self-preservation), ADR-005

#### Sequencia de execucao
- Fase 1: `application-local.yml` (self-preservation off, fast eviction).
- Fase 2: `application-prod.yml` (defaults, cluster hostname).

#### Criterios de aceite
- local → self-preservation disabled; prod → default; no hardcoded secrets.

#### Riscos
- Mis-tuned eviction flapping instances — validate via dashboard.

#### Instrucao para implementador
Keep all tunables behind `${VAR}`.

## 3. Dependencias externas
- Spring Cloud release train compatible with Spring Boot 3.5.x (Eureka Server starter).
- Container orchestrator exposing REG at a stable address before business services start.

## 4. Restricoes arquiteturais
- ArchUnit: only **RULE-09** applies (base package). RULE-01..06/08 are N/A (ADR-001).
- No hexagonal layers (no `api/application/domain/infrastructure` business packages).
- No `@Transactional`, no JPA, no DB, no messaging, no multi-tenancy.
- No hardcoded secrets — `${VAR}` only.
