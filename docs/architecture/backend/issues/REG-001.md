# REG-001 -- Scaffold Eureka Server application

## Contexto
REG is the Journey OS service-discovery authority. Its core is a standalone Spring Cloud
Netflix Eureka Server. This issue delivers the executable skeleton (entry point) in the
mandatory base package `com.journeyos.reg`.

## Spec de referencia
- SPEC-01-api-surface
- ADR-001 (reduced structure), ADR-002 (Eureka)

## Escopo
- `RegistryApplication` annotated `@SpringBootApplication @EnableEurekaServer`.
- Gradle subproject `:services:journey-os-service-registry` with the
  `spring-cloud-starter-netflix-eureka-server` + `spring-boot-starter-actuator` deps.
- No `api/application/domain/infrastructure` packages (none apply — ADR-001).

## Resultado esperado
`./gradlew :services:journey-os-service-registry:bootRun` starts a Eureka Server on 8761.

## Criterios de aceite
- [ ] `RegistryApplication` exists in package `com.journeyos.reg` (RULE-09).
- [ ] Application annotated `@EnableEurekaServer`.
- [ ] `compileJava` succeeds.
- [ ] Server boots and `GET /` returns the Eureka dashboard.
