# MIG-003 -- Schema-aware migration layout (global vs empresa)

## Contexto
As migrações são particionadas por destino de schema via path (ADR-003): um conjunto
global e um conjunto por tenant (`empresa`). O Flyway precisa ser configurado com as
duas locations e a estratégia de schema-alvo correta.

## Spec de referencia
- SPEC-04 (Data model & migrations)
- ADR-003 (schema partitioning), ADR-004 (multi-tenancy)

## Escopo
- Estrutura `src/main/resources/db/migration/global/` e `.../empresa/`.
- Configurar Flyway para aplicar `global/V*` em `journeyos_global` e `empresa/V*` em
  cada schema de tenant.
- Convenção de nome `V<N>__<module>_<description>.sql` documentada no README do serviço.

## Resultado esperado
Migrações global e por-tenant são resolvidas e aplicadas no schema correto, sem
ambiguidade.

## Criterios de aceite
- [ ] Diretórios `db/migration/global/` e `db/migration/empresa/` existem.
- [ ] `global/V*` aplica em `journeyos_global`.
- [ ] `empresa/V*` aplica em cada schema de tenant.
- [ ] Nenhuma migração aplica no schema errado (verificado por teste de integração).
