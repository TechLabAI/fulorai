# MIG-006 -- Idempotency & concurrency (schema history + lock)

## Contexto
Migrações devem aplicar exatamente uma vez por schema e execuções concorrentes de MIG
não podem corromper o schema nem o histórico.

## Spec de referencia
- SPEC-05 (idempotency & concurrency)
- ADR-002, ADR-005

## Escopo
- Garantir `flyway_schema_history` por schema (comportamento padrão Flyway).
- Confiar no lock do Flyway para serializar execuções concorrentes por schema.
- `validateOnMigrate=true` para detectar checksum drift / out-of-order.

## Resultado esperado
Re-execuções são seguras (no-op); execuções concorrentes serializam; drift falha rápido.

## Criterios de aceite
- [ ] Cada versão aplica uma única vez por schema.
- [ ] Execução concorrente aguarda o lock (não aplica em paralelo no mesmo schema).
- [ ] Checksum mismatch de migração já aplicada → falha de validação, sem prosseguir.
- [ ] Re-run sem pendências → no-op.
