# REG-003 -- Profile overlays + self-preservation tuning

## Contexto
Self-preservation must differ by environment: disabled locally (accurate dashboard during
dev), default in production (partition protection). See ADR-005.

## Spec de referencia
- SPEC-07-observability-health
- ADR-005 (health-check/self-preservation/HA)

## Escopo
- `application-local.yml`: `eureka.server.enable-self-preservation: false`,
  faster `eviction-interval-timer-in-ms`, `eureka.instance.hostname: localhost`.
- `application-prod.yml`: self-preservation at Eureka default (on),
  `eureka.instance.hostname: journey-os-service-registry`.
- Active profile via `${SPRING_PROFILES_ACTIVE:local}`.

## Resultado esperado
Profile selection changes eviction behavior and advertised hostname without code changes.

## Criterios de aceite
- [ ] WHILE `local` profile is active, self-preservation is disabled.
- [ ] WHILE `prod` profile is active, self-preservation stays at the Eureka default.
- [ ] No secrets hardcoded; all overrides via `${VAR}`.
