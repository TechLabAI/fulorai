# REG-002 -- Base application.yml (port, self-registration off, actuator exposure)

## Contexto
The Eureka Server must not register with itself and must expose a controlled Actuator
surface, all via environment-driven config (no hardcoded secrets).

## Spec de referencia
- SPEC-01-api-surface
- SPEC-07-observability-health
- contracts/api-contract.md §3

## Escopo
- `application.yml` with:
  - `server.port: ${SERVER_PORT:8761}`
  - `eureka.client.register-with-eureka: false`
  - `eureka.client.fetch-registry: false`
  - `management.endpoints.web.exposure.include: health,info`
  - `spring.application.name: journey-os-service-registry`

## Resultado esperado
REG boots as a non-self-registering server exposing only `health` and `info` Actuator endpoints.

## Criterios de aceite
- [ ] `register-with-eureka=false` and `fetch-registry=false` (invariant: REG does not register with itself).
- [ ] `GET /actuator/health` returns `{"status":"UP"}`.
- [ ] `GET /actuator/env` returns `404` (not exposed).
- [ ] Port resolved from `${SERVER_PORT:8761}`.
